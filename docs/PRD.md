## 2. 产品背景

大学社团通常需要同时处理对外展示、活动宣传、报名统计、成员管理、部门协作和福利发放等事务。如果只使用社交平台、表格或聊天群管理，容易出现以下问题：

- 社团信息分散，外部用户难以系统了解社团。
- 活动报名依赖手动统计，重复报名、名额控制和权限限制不好处理。
- 社团成员创建活动后缺少审核流程，发布内容不够规范。
- 部门成员、负责人和社长之间的权限边界不清晰。
- 优惠券、抢票、活动福利等高并发场景缺少可靠技术支持。
- 管理者缺少活动参与度、接口访问量等数据面板。

Club System Plus 旨在构建一个完整的社团网站系统，既能作为社团官网对外展示，也能作为内部活动和成员管理平台使用。

## 3. 产品目标

### 3.1 业务目标

- 建立一个统一的社团官网入口。
- 支持公开活动与社团内部活动的发布、报名和抢票。
- 支持社团成员按部门协作创建活动。
- 支持部门负责人审核活动变更。
- 支持社长和系统维护者进行全局管理。
- 支持优惠券领取、秒杀和用户券包。
- 提供基础运营数据面板。

### 3.2 用户目标

- 游客可以快速了解社团，并参与允许游客参与的公开活动。
- 注册用户可以报名公开活动、领取公开优惠券。
- 社团成员可以参加全部活动，并提交活动编辑申请。
- 部门负责人可以管理本部门成员和审核活动申请。
- 社长可以管理组织架构、活动和核心运营数据。
- 系统维护者可以查看系统访问量、接口数据和维护配置。

### 3.3 技术目标

- 使用 Spring Boot + MySQL + Redis 构建后端核心服务。
- 使用 Vue 3 + TypeScript 构建前端用户端和管理端。
- 使用 JWT 和 RBAC 实现认证与授权。
- 使用 Redis/Lua/分布式锁处理抢券、抢票等库存并发问题。
- 支持后续 Docker Compose 部署。

## 4. 产品范围

### 4.1 MVP 范围

MVP 阶段必须完成：

- 官网展示
- 用户注册登录
- 角色权限控制
- 部门与成员管理
- 活动创建、展示、报名
- 活动编辑审核
- 基础后台管理

### 4.2 非 MVP 范围

以下功能放到第二阶段或之后：

- 专业监控系统
- 移动端 App
- 多社团租户系统

## 5. 用户角色

### 5.1 游客

定义：未登录用户。

能力：

- 浏览首页、社团介绍、组织结构、公开活动。
- 查看公开活动详情。

限制：

- 不能参加仅限登录用户或社团成员的活动。
- 不能领取仅限注册用户或社团成员的优惠券。
- 不能访问个人中心、成员中心或后台。

### 5.2 注册用户

定义：已完成注册登录，但不是社团成员。

能力：

- 拥有游客全部能力。
- 报名公开活动。
- 领取公开优惠券。
- 查看个人报名记录和优惠券。

限制：

- 不能参加仅限社团成员的活动。
- 不能创建、编辑、审核活动。
- 不能访问社团成员管理功能。

### 5.3 社团普通成员

定义：已经加入社团，并归属于某个部门。

能力：

- 拥有注册用户全部能力。
- 参加所有允许成员参加的活动。
- 领取社团成员专属优惠券。
- 创建活动申请。
- 提交活动修改申请。
- 提交活动取消申请。
- 查看自己提交的申请状态。

限制：

- 不能直接发布活动。
- 不能直接修改已发布活动。
- 不能审核自己的活动申请。
- 不能管理部门成员。

### 5.4 部门负责人

定义：负责一个或多个部门的社团管理者。

能力：

- 拥有普通成员全部能力。
- 管理本部门成员。
- 创建、编辑本部门活动。
- 审核本部门普通成员提交的活动申请。
- 查看本部门活动和成员数据。

限制：

- 默认不能管理其他部门成员。
- 默认不能创建或删除部门。
- 默认不能任命其他部门负责人。

### 5.5 社长

定义：社团最高管理角色。

能力：

- 拥有部门负责人全部能力。
- 管理所有部门。
- 添加、移除部门负责人。
- 添加、移除社团成员。
- 审核或强制处理所有活动申请。
- 发布、取消任意活动。
- 查看后台运营面板。

### 5.6 系统开发/维护者

定义：负责系统技术维护的管理员。

能力：

- 拥有社长绝大部分管理能力。
- 查看接口访问量。
- 查看系统异常和操作日志。
- 管理系统配置。
- 维护基础字典、接口限流和系统开关
- 发布停机维修类似的公告

限制：

- 不建议默认参与社团业务决策，例如活动内容审核可交给社长。

## 6. 核心业务流程

### 6.1 注册登录流程

1. 用户进入注册页。
2. 输入用户名、邮箱或手机号、密码。
3. 系统校验账号是否重复。
4. 系统加密密码并创建用户。
5. 用户登录。
6. 系统签发 JWT。
7. 前端保存 token，并根据角色加载菜单。

异常场景：

- 用户名已存在。
- 密码强度不足。
- 登录密码错误。
- token 过期。
- 用户被禁用。

### 6.2 活动创建与审核流程

1. 社团普通成员进入成员中心。
2. 点击创建活动。
3. 填写活动标题、类型、时间、地点、人数限制、参与限制、详情等信息。
4. 保存草稿或提交审核。
5. 系统创建活动变更申请。
6. 部门负责人收到待审核申请。
7. 负责人选择通过或拒绝。
8. 通过后，系统创建正式活动并发布。
9. 拒绝后，申请人可查看拒绝原因并重新编辑提交。

规则：

- 普通成员提交的活动不能直接发布。
- 部门负责人只能审核本部门成员提交的申请。
- 社长可以审核所有申请。
- 系统需要记录审核日志。

### 6.3 活动报名流程

1. 用户进入活动详情页。
2. 点击报名。
3. 系统校验登录状态。
4. 系统校验活动状态和报名时间。
5. 系统校验用户角色是否满足活动限制。
6. 系统校验是否重复报名。
7. 系统校验剩余名额。
8. 报名成功后生成报名记录。
9. 用户可在个人中心查看报名记录。

异常场景：

- 活动未发布。
- 报名未开始或已结束。
- 用户角色不满足。
- 名额已满。
- 用户已报名。

### 6.4 抢票流程

1. 管理者创建限量抢票活动。
2. 系统提前将库存加载到 Redis。
3. 用户在开放时间点击抢票。
4. Redis Lua 脚本校验库存和重复抢票。
5. 抢票成功后返回排队成功或抢票成功。
6. 系统异步写入数据库。
7. 用户在个人中心查看结果。

规则：

- 同一用户同一活动只能抢一次。
- 库存不能超卖。
- 数据库写入失败时需要补偿。

### 6.5 优惠券领取流程

1. 管理者创建优惠券批次。
2. 设置名称、库存、领取时间、适用角色、过期时间。
3. 用户进入优惠券页面。
4. 系统展示可领取优惠券。
5. 用户点击领取。
6. 系统校验资格、库存和重复领取。
7. 领取成功后加入用户券包。

### 6.6 部门成员管理流程

1. 社长创建部门。
2. 社长任命部门负责人。
3. 部门负责人添加本部门成员。
4. 成员获得社团成员权限。
5. 成员可以参与内部活动和提交活动申请。

规则：

- 普通成员必须归属于一个部门。
- 部门负责人可以属于多个部门（maybe）
- 删除部门前需要处理部门下成员和活动。

## 7. 功能需求

### 7.1 官网展示

#### 7.1.1 首页

功能说明：

- 展示社团名称、核心介绍、近期活动、重要公告。
- 提供登录、注册、活动入口。

验收标准：

- 游客可访问首页。
- 首页可跳转到社团介绍、活动列表、登录注册。
- 首页展示至少 3 个近期活动或空状态。

#### 7.1.2 社团背景介绍

功能说明：

- 展示社团成立背景、宗旨、发展方向、主要成就。

验收标准：

- 游客可访问。
- 管理员可在后期维护内容。

#### 7.1.3 重要人员介绍

功能说明：

- 展示社长、部门负责人和核心成员。

验收标准：

- 支持按部门展示。
- 人员信息至少包括头像、姓名、职位、简介。

#### 7.1.4 组织结构介绍

功能说明：

- 展示部门层级和职责。

验收标准：

- 能看到所有公开部门。
- 能进入部门详情页。

### 7.2 认证与用户

#### 7.2.1 注册

功能说明：

- 用户通过用户名、邮箱或手机号注册账号。

验收标准：

- 密码加密存储。
- 账号唯一。
- 注册成功后可登录。

#### 7.2.2 登录

功能说明：

- 用户登录后获得 token。

验收标准：

- 登录成功返回用户基础信息和角色。
- 登录失败返回明确错误。
- token 过期后需要重新登录或刷新。

#### 7.2.3 个人中心

功能说明：

- 用户查看个人资料、报名记录、优惠券。

验收标准：

- 登录用户可访问。
- 游客访问时跳转登录页。

### 7.3 活动

#### 7.3.1 活动列表

功能说明：

- 展示公开活动和用户可参与活动。
- 支持按活动类型、状态、时间筛选。

验收标准：

- 游客只能看到公开活动。
- 登录用户可看到自己有权限查看的活动。
- 活动列表支持分页。

#### 7.3.2 活动详情

功能说明：

- 展示活动完整信息、报名状态和剩余名额。

验收标准：

- 已结束活动不可报名。
- 已取消活动显示取消状态。
- 用户已报名时显示已报名状态。

#### 7.3.3 活动创建

功能说明：

- 成员、负责人、社长、维护者可以创建活动。

验收标准：

- 普通成员创建后进入待审核。
- 负责人创建本部门活动可直接发布或走审核，具体由配置决定。
- 社长和维护者可直接发布。

#### 7.3.4 活动修改

功能说明：

- 修改活动标题、时间、地点、详情、名额、参与限制。

验收标准：

- 普通成员修改需要审核。
- 已有人报名的活动修改关键字段时需要提示风险。
- 修改记录可追踪。

#### 7.3.5 活动取消

功能说明：

- 取消已发布活动。

验收标准：

- 普通成员提交取消申请。
- 负责人或社长审核后取消。
- 活动取消后不可继续报名。

### 7.4 报名与抢票

#### 7.4.1 普通报名

功能说明：

- 用户报名普通活动。

验收标准：

- 不允许重复报名。
- 人数不能超过限制。
- 不满足角色限制时禁止报名。

#### 7.4.2 取消报名

功能说明：

- 用户可在报名截止前取消报名。

验收标准：

- 取消后释放名额。
- 报名截止后是否可取消由活动配置决定。

#### 7.4.3 限量抢票

功能说明：

- 用于大型活动或限量活动。

验收标准：

- Redis 库存不超卖。
- 同一用户不能重复抢票。
- 抢票结果可查询。

### 7.5 优惠券

#### 7.5.1 优惠券批次创建

功能说明：

- 管理者创建优惠券活动。

验收标准：

- 可设置库存、领取时间、过期时间、角色限制。
- 库存必须大于 0。

#### 7.5.2 优惠券领取

功能说明：

- 用户领取符合条件的优惠券。

验收标准：

- 不允许重复领取同一批次。
- 不允许超过库存。
- 不符合角色限制时不可领取。

#### 7.5.3 用户券包

功能说明：

- 用户查看自己的优惠券。

验收标准：

- 按未使用、已使用、已过期分类展示。

### 7.6 部门与成员

#### 7.6.1 部门管理

功能说明：

- 社长和维护者管理部门。

验收标准：

- 可创建、编辑、停用部门。
- 部门名称唯一。
- 停用部门前需要处理成员归属。

#### 7.6.2 成员管理

功能说明：

- 管理社团成员和部门归属。

验收标准：

- 社长可管理所有成员。
- 部门负责人可管理本部门成员。
- 普通成员不能访问成员管理页。

#### 7.6.3 负责人管理

功能说明：

- 社长任命和移除部门负责人。

验收标准：

- 一个部门可有多个负责人。
- 负责人必须是已注册用户。

### 7.7 审核中心

功能说明：

- 展示活动创建、修改、取消申请。

验收标准：

- 普通成员只能查看自己提交的申请。
- 部门负责人只能查看本部门待审核申请。
- 社长可查看全部申请。
- 审核必须填写通过或拒绝结果。
- 拒绝时必须填写原因。

### 7.8 后台数据面板

功能说明：

- 展示系统和业务数据。

指标：

- 用户总数
- 社团成员总数
- 部门数量
- 活动数量
- 报名人数
- 优惠券领取数量
- 今日接口访问量
- 最近 7 天访问趋势
- 接口流量排名

验收标准：

- 社长和维护者可访问。
- 其他角色不可访问。
- 数据至少每5分钟自动更新或者手动刷新更新。

## 11. 非功能需求

### 11.1 性能

- 普通页面接口响应时间应小于 500ms。
- 活动列表和报名列表需要分页。
- 抢券/抢票接口需要支持短时间高并发请求。

### 11.2 安全

- 密码必须加密存储。
- 所有管理接口必须鉴权。
- 前端隐藏按钮不能替代后端权限校验。
- JWT 需要设置过期时间。
- 关键操作需要记录操作日志。

### 11.3 可用性

- 用户操作失败时需要给出明确提示。
- 活动、报名、优惠券等列表需要空状态展示。
- 管理后台需要支持按条件筛选。

### 11.4 可维护性

- 后端使用分层结构。
- 统一响应格式。
- 统一异常处理。
- 接口文档自动生成。
- 核心业务需要单元测试或集成测试。

## 12. 风险与待确认问题

### 12.1 风险

- 权限模型复杂，早期需要设计清楚角色、部门和数据范围。
- 抢券/抢票涉及并发一致性，建议 MVP 后再做。
- 活动审核如果设计过重，会拖慢早期开发进度。
- 后台数据面板如果追求实时监控，会增加系统复杂度。

### 12.2 待确认问题

- 游客是否允许直接报名活动，还是必须先注册。
- 部门负责人创建活动是否需要社长二次审核。
- 社团成员加入方式是由管理员添加，还是用户申请加入后审核。
- 优惠券是否需要真实核销流程。
- 是否需要邮件或站内信通知审核结果。
- 是否需要中英文双语页面。
