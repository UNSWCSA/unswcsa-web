# 新南学联网站简化改造背景

最后更新：2026-09-24。六个页面的展示内容、编辑范围和不做的功能已由用户确认，摘要见 `page-scope-checklist.md`；账号权限及技术选型仍按实施阶段落实。

## 项目定位

新版网站是新南学联的官方品牌展示、活动信息和加入入口。

网站主要负责：

- 展示学联形象、部门、团队和成果。
- 展示已经结束的代表性品牌活动。
- 自动展示 Eventbrite 中的普通活动。
- 引导用户前往 Eventbrite 报名。
- 提供招新、联系方式和社交媒体入口。

网站不再承担公众用户系统、票务系统或社团内部业务管理系统的职责；仅新增受邀管理层使用的轻量 `/admin` 内容编辑入口。

## 设计和内容原则

- 页面保持简洁，不大量堆砌文字。
- 不增加没有明确用途的筛选项、字段或详情。
- 首页只展示最重要的信息。
- 使用学联真实照片和官方品牌视觉。
- 普通活动的事实信息以 Eventbrite 为唯一来源。
- 非技术负责人应能完成日常内容维护。
- 内容负责人只能修改文字、图片、链接、顺序、公开状态和预设颜色，不能修改布局、字体、CSS、HTML 或动画。
- 网站保留自研 React 前端的设计自由度，不采用 Wix、Squarespace 等模板式建站方案。
- 所有颜色、Logo、字体、背景纹样和图片使用必须遵守 `context/brand-guidelines.md`。
- 品牌资产必须优先使用 `frontend/public/brand/` 中已有的正式文件，不自行重绘或使用截图替代。
- 组织名称和简写方式遵守 `context/brand-guidelines.md`。

## 系统架构边界

内容后台与 Eventbrite 是两个独立数据源，不通过统一的 CSA 业务后端管理。

- 自建 `/admin` 只负责官网固定内容，通过登录验证和服务端内容保存接口写入 GitHub 内容文件，触发自动构建发布；不再选用外部 CMS 产品。
- 访客读取成功部署的已发布内容，不在每次访问时请求 GitHub；技术部在 GitHub 修改页面代码并自动构建发布。
- 仅受邀管理层可以登录，不开放公众注册，不恢复旧会员、RBAC、报名或优惠券功能。
- 草稿保存在私有仓库，预览需要登录，新上传未发布图片默认受保护，发布时才开放确认版本；代码仓库若保持公开，则使用独立私有内容仓库。具体仓库布局在 PoC 中确定。
- 技术部编辑前沟通并错开时间，仅保留简单版本检查，不开发复杂协同编辑或自动合并。
- 写入、草稿、图片和发布边界见 `admin-publishing-architecture.md`；已公开内容撤下不保证重新保密。
- Eventbrite 只负责普通活动和报名。
- Event API / Cache 只负责读取、转换 Eventbrite 数据及可选的缓存；缓存不是故障恢复的必要条件。
- React 在展示层读取并组合两个数据源。
- 内容保存接口与 Eventbrite 只读接口保持独立，不建设管理全部业务的通用后端；两者可部署在同一平台但不互相依赖。
- 任一数据源都应能够在不影响另一数据源的情况下替换。

## 导航结构

一级导航保留六项：

1. 首页
2. 关于我们
3. 部门与团队
4. 品牌活动
5. 全部活动
6. 加入我们

不单独设置联系我们页面。联系方式放在关于我们页面和网站页脚。

## 首页

首页按以下顺序展示：

1. 学联 Logo 和 Slogan
2. 学联简介
3. 学联荣誉与影响力
4. 品牌活动入口
5. 加入学联入口
6. Instagram、小红书、微信公众号、抖音等社交入口
7. 页脚

首页不展示复杂统计、完整部门名单或大量活动卡片。

### 学联简介

使用一至两段短文说明学联是谁、服务哪些学生以及主要开展什么工作。详细介绍放在关于我们页面。

### 学联荣誉与影响力

使用简短的 bullet point 列举，不为每项荣誉建立复杂卡片或详情页。只保留经过确认的重要奖项、认可和代表性成果。

### 品牌活动入口

展示少量代表性品牌活动卡片。每张卡片只包含封面、名称、一句话介绍和查看详情按钮。

### 加入学联入口

使用简短文案和明确的加入我们按钮。

## 关于我们

包括：

- 学联中英文全称。
- 学联定位。
- 愿景与使命。
- 简短发展历史。
- 与 UNSW、Arc 或相关组织经核实的正式联系，不指内部上下级关系，不将注册或合作事实扩大为官方背书。
- 联系方式。

联系方式放在页面末尾，包括一般咨询邮箱、商务或合作邮箱、Instagram、小红书、微信公众号、抖音和 Eventbrite。

不增加复杂联系表单。

## 部门与团队

页面分为部门介绍和团队成员。

### 部门介绍

每个部门只展示：

- 部门名称。
- 简短介绍。
- 部门图片或图标。

部门介绍控制在一小段内，不展开内部流程和复杂职责。

### 本届团队

默认展示当前年份，例如 `2026 团队`。

每位成员只展示：

- 姓名。
- 职位。
- 照片。

### 往届团队

严格按照自然年归档，例如：

- 2026 团队
- 2025 团队
- 2024 团队

用户通过年份切换查看往届团队。不为每位成员增加个人简介、个人社交账号或独立详情页。

## 品牌活动

品牌活动只展示已经结束、具有代表性和长期传播价值的活动，不承担当前活动报名。

可能包括新生行前会、中秋国庆晚会、游轮活动、电竞赛事、职业发展项目以及迎新和福利活动。

### 品牌活动列表

每张卡片只展示：

- 名称。
- 封面。
- 短介绍。

### 品牌活动详情

页面只展示：

- 名称。
- 短介绍。
- 封面。
- 重要数据。
- 精选照片。

内容后台管理字段包括：

- 主题颜色，或所有品牌活动使用统一颜色。
- 显示顺序。
- 是否公开。

重要数据保持简洁，例如参与人数、举办城市或合作高校数量。

如果允许单独设置主题颜色，应从少量预设颜色中选择，不允许负责人输入任意颜色。

## 全部活动

普通活动统一从 Eventbrite 获取。网站不处理报名、票务、退款、名额、参与者名单和签到。

### 活动筛选

只保留：

- 年份。
- 月份。

不增加活动类型、部门、标签或复杂状态筛选。

### 活动状态

即将举行和往期活动不作为筛选项，状态直接显示在活动卡片上：

- 即将举行。
- 进行中。
- 已结束。
- 已取消。

状态根据活动时间和 Eventbrite 状态自动确定，不由负责人手动维护。

### 活动卡片

只展示：

- 封面。
- 活动名称。
- 日期。
- 地点。
- 状态。
- 简短介绍。
- 报名或查看按钮。

即将举行的活动显示前往 Eventbrite 报名。已结束的活动显示查看活动。品牌活动作为独立内容展示，不要求与 Eventbrite 活动建立数据关联。

### 活动详情

只展示标题、封面、简短介绍、时间、地点、状态和 Eventbrite 链接。完整报名信息以 Eventbrite 为准，官网不重复维护。

## 加入我们

页面包括：

- 为什么加入。
- 部门简介。
- 招新时间。
- 简短招新流程。
- 常见问题。
- 申请入口。

招新开放时显示截止时间、开放部门、申请流程和申请按钮。

招新关闭时显示当前暂未开放招新，并引导用户关注社交媒体。后台只需切换招新状态并更新申请链接。

## 页脚

所有页面使用统一页脚，包含：

- 学联中英文名称。
- 官方邮箱。
- Instagram。
- 小红书。
- 微信公众号。
- 抖音，中国区 TikTok。
- Eventbrite。
- 版权信息。

## 内容管理要求

官网内容维护与 Eventbrite 活动管理由每年的管理层负责，技术维护由技术部同学负责。年度换届应交接对应账号权限与维护资料；不开发自动到期或自动撤销离任权限，允许继续协助的人员保留权限，同时保留人工撤销方式。

身份、图片存储和部署等服务统一使用学联公共邮箱注册，由管理层持有账号，技术部获得维护权限；具体邮箱、成员邀请和权限配置在产品确定后落实。

正式资料清单在后续页面布局调整后按实际内容区块建立并补充，不要求在第二阶段提前收齐；正式上线前由管理层核实必需内容，不自行编造资料。

为非技术负责人提供网站内 `/admin` 固定表单，不要求管理层操作 GitHub。服务端逐次验证身份、字段和文件路径。栏目只包含：

- 首页。
- 关于我们。
- 部门。
- 团队。
- 品牌活动。
- 加入我们。
- 网站设置。

普通活动不在内容后台重复录入。

- 内容后台数据模型不保存普通活动副本。
- Eventbrite 活动缓存不存储在内容后台中。
- 内容后台不读取或修改 Eventbrite 活动数据。
- Event API / Cache 不读取或修改官网内容。
- 两类数据只在 React 展示层组合。

## 活动同步要求

技术部需要 Eventbrite API 访问时联系技术部部长；部长具有账号访问权限，必要时联系其他管理层同学协调授权。实际 API 权限、凭据配置和真实活动读取在第三阶段验证。

- 活动负责人只在 Eventbrite 创建和发布普通活动。
- 网站定时读取 Eventbrite 活动，建议每小时一次。
- Eventbrite 读取或同步失败时，活动列表和详情显示“活动信息暂时无法加载，请稍后重试”，不能显示“暂无活动”。自动重试或定时同步继续运行，后续成功读取后自动恢复展示，无需手动部署。故障只影响活动列表和详情，不影响首页、团队、品牌活动等官网内容页面的展示与发布。
- 不要求故障期间继续展示旧数据，也不要求持久保存最后成功快照；缓存仅作为可选优化。
- 成功返回空列表与读取失败必须区分，分页请求部分失败不能被当作完整成功结果。
- 在 PoC 中确定重试或同步间隔、恢复延迟和已打开页面的恢复方式；不能依赖人工重新部署恢复。
- 网站根据时间自动计算活动状态。
- 报名按钮跳转 Eventbrite。
- 时间统一使用 `Australia/Sydney` 时区。
- Eventbrite 凭据只能保存在服务端环境变量中，不能暴露给浏览器。
- Event API / Cache 是独立的只读适配层，不发展成新的通用业务后端。

## 技术方向

保留：

- React。
- TypeScript。
- Vite。
- React Router。
- 自研页面和视觉组件。

新增：

- 自建 `/admin`、受邀管理层登录、服务端内容保存接口、GitHub 内容文件与自动构建发布。
- 图片使用独立存储，GitHub 内容保存图片引用；草稿和预览受访问控制，发布失败继续提供上一成功部署。
- Eventbrite 同步功能。
- 活动数据读取失败提示、自动重试或定时同步及成功后的自动恢复；缓存可选。
- 自动构建与部署。
- 基础 SEO 和社交分享信息。
- 图片尺寸限制和自动压缩。
- 独立的 Content Source 和 Event Source 数据适配层。

移除或退役：

- 旧公众注册、登录和找回密码；新增的受邀管理层登录独立实现。
- 个人资料、我的活动和我的优惠券。
- 自建活动报名和活动审批。
- 成员权限和 RBAC。
- 优惠券和抢券。
- 美食地图和餐厅评论。
- AI 助手。
- 复杂数据面板。
- Spring Boot 业务后端。
- MySQL、Redis、RabbitMQ 和 MinIO。
- JWT、SMTP、Sentinel 和相关复杂基础设施。

## 验收标准

- 网站只有六个一级导航入口；品牌活动和普通活动详情页不进入一级导航。
- 首页内容简短且重点明确。
- 荣誉与影响力使用 bullet point。
- 联系方式位于关于我们页面和页脚。
- 团队按照自然年归档。
- 品牌活动只展示已经结束的代表性活动。
- 活动只提供年份和月份筛选。
- 活动状态直接显示在卡片上。
- 普通活动全部来自 Eventbrite。
- 官网不保存报名者或普通用户资料；身份服务只维护必要的受邀编辑者身份和访问权限。
- 非技术负责人可以维护团队、品牌活动和招新信息。
- 日常维护不需要修改代码。
- Eventbrite 读取或同步失败时，活动列表和详情显示“活动信息暂时无法加载，请稍后重试”，不能显示“暂无活动”。自动重试或定时同步继续运行，后续成功读取后自动恢复展示，无需手动部署。故障只影响活动列表和详情，不影响首页、团队、品牌活动等官网内容页面的展示与发布。
- 新版不再依赖现有复杂业务基础设施。
- 手机端、平板和桌面端均可正常使用。
