# 新南学联网站改造上下文入口

本目录是新版网站简化改造的主要背景资料。没有此前对话记录时，应先阅读本文件，再按以下顺序阅读：

1. `website-simplification-context.md`：确定产品范围、页面结构、数据来源和明确不做的功能。
2. `brand-guidelines.md`：确定品牌名称、颜色、字体方向和正式资产的使用规则。
3. `implementation-plan.md`：确定实施顺序、验证要求和旧系统退役条件。
4. `project-status.md`：确认当前进度、已经确定的事项和仍待决定的事项。

六个页面范围已于 2026-09-23 经用户确认，实施基线见 `page-scope-checklist.md`，集中查看六个页面的展示内容、编辑权限和不做的功能；该清单依据需求背景整理，不替代正式资料收集。

当前架构已更新为自建 `/admin` + GitHub 内容文件 + 自动构建发布，详见 [内容后台与发布架构](admin-publishing-architecture.md)。此前外部 CMS 产品选型被此方案替代；这里的“内容后台”专指新建轻量编辑器，不是旧 AdminView。

草稿与编辑规则也已确认：私有保存草稿，登录后预览，新上传未发布图片受保护；技术部通过提前沟通错开编辑，系统保留简单版本检查。具体配置由 Step 3 验证。

Step 3 已有独立 [本地原型](../frontend/poc/README.md) 和 [Cloudflare/GitHub 接入实现与配置说明](../cloud/README.md)。真实云端登录、发布和 Eventbrite 验收尚未完成。

## 文档优先级

- 新版简化改造以本目录中的文件和用户最新明确要求为准。
- 仓库原有 README、PRD、代码和配置用于理解现状，不代表新版仍需保留原有功能。
- 如本目录内部出现冲突，以用户最新明确要求为准；不能确认时先提出问题，不自行扩大需求。
- 品牌手册和 `frontend/public/brand/` 中的正式资产优先于文字推断。

## 执行约束

- 按 `implementation-plan.md` 分阶段实施，不跳过内容后台和 Eventbrite PoC。
- 内容后台与 Eventbrite 保持独立，不重新建立承载全部业务的通用后端。
- Eventbrite 读取或同步失败时，活动列表和详情显示“活动信息暂时无法加载，请稍后重试”，不能显示“暂无活动”。自动重试或定时同步继续运行，后续成功读取后自动恢复展示，无需手动部署。故障只影响活动列表和详情，不影响首页、团队、品牌活动等官网内容页面的展示与发布。不强制保留旧活动快照，缓存仅为可选优化。
- 在新版完成验证、数据完成迁移且得到明确确认前，不物理删除旧系统或旧数据。
- 不为了补全页面自行编造学联资料、团队成员、奖项、活动数据、联系方式或社交账号。
- 每完成一个阶段或确认一项关键选型，应同步更新 `project-status.md`。
