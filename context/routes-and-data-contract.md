- `/departments`、`/leaders` 重定向至 `/team`。没有核实映射的旧活动 ID 不转换成 Eventbrite ID；旧业务路径不挂载旧页面，默认进入 404。
- `/admin` 骨架可先引导至现有 Access 保护的后台，明确发布仍作用于当前 PoC；正式同域整合另行验证。

## 数据边界

- **Content Source**：读取成功部署的静态公开快照；一次读取绑定同一发布版本。包括首页、关于、部门、团队、招新和网站设置，不包含普通活动、草稿、身份名单或密钥。
- **Event Source**：只读独立 Worker 的公开活动列表，不访问内容后台。浏览器不直接请求 Eventbrite 原始 API；本地使用 Vite 同源代理，生产构建附带 Pages 同源转发 Worker；云端部署验收待完成。
- 管理层在新后台维护官网内容，在 Eventbrite 维护普通活动；布局、样式和交互由代码维护。两个来源不互相写入，也不成为对方展示或发布成功的前置条件。
- 邮箱和社交链接统一取网站设置；加入页通过部门 ID 复用部门介绍。数组顺序即展示顺序，公开快照仅含已公开条目。
- 图片引用只有 URL 和替代文字；未发布图片不得进入公开快照。

## 读取与状态

- 类型入口：[content.ts](../frontend/site/sources/content.ts)、[events.ts](../frontend/site/sources/events.ts)。Content Source 仍仅声明类型；Event Source 已实现同源 `/api/events` 读取、运行时校验、超时及取消，页面负责刷新与重试。
- 页面使用 `loading / success / not-found / error`；空列表是成功结果。未补充页面用 `null` 表达，不能把缺失或读取失败解释为招新关闭。
- 内容请求失败显示不可用；网络或上游失败属于 error。站内不再读取活动详情。
- Eventbrite 失败显示“活动信息暂时无法加载，请稍后重试”。沿用 PoC 的每 60 秒请求及返回前台重试，成功后自动恢复；取消订阅或切换页面时停止旧请求与定时器。实际恢复延迟仍需验证。
- 活动状态在展示时随当前时间计算：取消优先，其次上游已结束或已超过结束时间，再判断进行中／即将举行；时间展示及年月筛选统一使用 `Australia/Sydney`，状态不能只在请求成功时更新。
- 列表只接受完整成功结果；分页部分失败不得伪装为空或完整列表。读取层须校验外部 JSON、时间、ID、链接和引用，TypeScript 类型不替代运行时校验。
- `ReadOptions.signal` 用于取消请求；主动取消不显示服务故障。`retryable` 表示是否适合自动重试；活动临时读取失败继续重试，无详情请求。

## 阶段边界

现有云端内容只有 `introduction` 字段，不能直接当作完整 `PublishedContent`。接入时通过适配转换并明确未补齐内容，不能用类型断言假装模型已实现。团队、招新及图片的写入和发布结构仍需 Step 3 验证；列表 SEO／分享、预览部署和跨域方案在 Step 4 落实。旧系统继续保留，当前约定不触发部署或正式站切换。

2026-10-07 年报导入说明：当前团队页以 2025、2026 作为两届任期的结束年份选择键，同时显示 2024/25、2025/26 完整任期，原自然年快照规则不直接应用于这批年报资料。静态内容尚未接入 Content Source；未来正式模型需保留任期标签，不能将两届名单误写为自然年成员快照。
