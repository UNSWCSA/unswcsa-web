# 首页简介本地 PoC

这是 Step 3 的本地开发部分，不代表真实身份验证、GitHub 发布或 Eventbrite PoC 已通过。旧前端继续使用原有 `npm run dev`，此入口独立运行。

## 启动

在 `frontend` 目录执行：

```sh
npm ci
npm run dev:poc
```

- 展示页：`http://127.0.0.1:5174/`
- 编辑页：`http://127.0.0.1:5174/admin`
- 已保存草稿预览：`http://127.0.0.1:5174/admin/preview`

点击“进入本地测试会话”，修改简介，保存草稿，预览，再发布。刷新展示页查看结果。恢复上一版本仅修改公开内容，保留草稿。尚未保存的输入不会出现在预览里。

## 边界

- 仅监听本机，测试登录不验证邮箱，不能用于生产或通过隧道公开。会话有效期一小时，重启服务后失效。
- 草稿和已发布内容保存在仓库根目录 `local-data/poc/content.json`，被 Git 忽略，不在公开资源目录中。只使用测试文字。
- 本地发布是原子替换 JSON 中的公开版本，不运行 GitHub 提交或云端构建。公开读取适配层目前也使用本地接口，尚未验证生产静态产物的故障隔离。
- 服务端只接受固定字段与版本号；并发保存和重复发布被版本检查拒绝。写入失败保留原文件。恢复按钮只用于 PoC 验证，正式版仍由技术部通过 Git 和部署平台恢复，不扩展管理层历史界面。
- React 以纯文字渲染简介，不支持 HTML、任意文件路径或布局编辑。
- `npm run build:poc` 仅检查类型和前端打包；生成的 `dist-poc` 不包含本地 API，不是可直接上线的完整系统，也不包含草稿数据。

## 验证

```sh
npm run test:poc
npm run build:poc
```

自动测试涵盖草稿与公开版本隔离、恢复、并发与重复请求、非法字段、存储失败、未登录访问、跨来源写入和退出会话。2026-09-24：四项测试与构建通过，浏览器验证登录、编辑、草稿预览、发布前后公开内容变化。
